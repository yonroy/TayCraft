Chat template — gói hội thoại + mặt nạ loss

PHẦN I · LLM
Họ tên: Ngày: ~14 phút prompt · mặt nạ 0 đếm mốc · loss trả lời · mặt nạ 1
🎯 Nhiệm vụ. Chat template gói hội thoại bằng token đặc biệt (mốc mở/đóng + nhãn vai) để mô hình biết "ai nói, đến lượt ai". Bạn sẽ đếm số mốc (m tin nhắn → 2m+1) rồi tính loss huấn luyện có mặt nạ: chỉ token phần trả lời (assistant) được tính loss, token phần prompt bị che (mặt nạ = 0). Cuối phiếu bạn tự chứng minh: đổi loss ở token prompt thì loss tổng ĐỨNG YÊN → gradient trên prompt = 0 → mô hình chỉ học cách trả lời, không học vẹt câu hỏi.
Dữ liệu cho sẵnchuỗi token phẳng · mặt nạ & loss mỗi token
Hội thoại 2 tin nhắn (system, user) rồi mở lượt assistant.
Mỗi tin nhắn = ‹start› + vai + nội dung + ‹end›.
Cuối chuỗi thêm ‹start›assistant (không ‹end›) → mô hình viết tiếp.
Mặt nạ loss: token thuộc prompt (system+user) → nhãn 0 (không tính loss); token assistant sinh ra → nhãn 1 (có tính loss).

Chat template — lời giải

ĐÁP ÁN
Bấm 🎲 Đổi số để luyện bộ số khác prompt · mặt nạ 0 đếm mốc · loss trả lời · mặt nạ 1
Sơ đồ đã điềnchuỗi token → mặt nạ → loss trung bình (chỉ phần trả lời)
Ví dụ template thật — ChatMLmột tin nhắn đóng kín + lượt assistant mở
‹im_start›system Bạn là trợ lý. ‹im_end›
‹im_start›user Chào bạn ‹im_end›
‹im_start›assistant ▮ ← đây là chỗ mô hình viết tiếp (chưa có ‹im_end›)
2 tin nhắn đóng kín (mỗi cái 1 ‹im_start› + 1 ‹im_end›) + 1 ‹im_start›assistant mở cuối chuỗi. Mỗi model một kiểu mốc (ChatML dùng ‹im_start›/‹im_end›; Llama, Gemma dùng ký hiệu khác).
① Đếm token đặc biệt (mốc)
‹start› = m+1 = 2+1 = 3  ·  ‹end› = m = 2  ·  tổng = 2m+1 = 5
Vì sao start nhiều hơn end 1: mỗi tin nhắn đóng kín góp 1 start + 1 end; riêng lượt assistant cuối mở (thêm 1 start, chưa end) để mô hình biết tới lượt mình viết tiếp.
② Loss huấn luyện có mặt nạ
Tử = 1·1.0 + 1·1.5 + 1·0.5 + 0·2.0 + 0·2.5 = 3.0
Mẫu = Σ mặt nạ = 1+1+1+0+0 = 3  →  L = tử ÷ mẫu = 1.0
L̄ nhầm (chia cả 5 token) = ( 3.0 + 2.0 + 2.5 ) ÷ 5 = 1.4
Tô thanhL (có mặt nạ)L̄ (nhầm)
giá trị
Vì sao che prompt: ta muốn mô hình học cách trả lời, không học vẹt câu hỏi của người dùng. Tính loss trên prompt sẽ ép mô hình "sinh ra" cả câu hỏi — vô nghĩa và làm loãng tín hiệu học. Hai thanh khác nhau → quên mặt nạ là tính SAI loss.
③ Tự kiểm — token prompt có gradient = 0
Nhân đôi loss p₁: 2.0 → 4.0. Tử mới = r₁+r₂+r₃ + 0·4.0 = 3.0  →  L mới = 1.0 = L cũ. KHÔNG đổi.
Đây là điểm cốt lõi: mặt nạ 0 nhân với loss prompt cho đúng 0 — nên token prompt không đóng góp gì vào L. Do đó đạo hàm ∂L/∂(dự đoán tại token prompt) = mặt nạ = 0: dù mô hình đoán token prompt đúng hay sai, gradient bằng 0, tham số không bị cập nhật vì phần prompt. Bấm 🎲 đổi loss prompt cỡ nào, L vẫn chỉ phụ thuộc các token trả lời — chính sự "đứng yên" đó là bằng chứng mô hình chỉ học phần trả lời.
Sai lầm thường gặp4 bẫy khi gói template & tính loss
✗ "Tính loss trên cả prompt cho nhiều dữ liệu hơn."
Sai — ép mô hình học sinh ra câu hỏi của người dùng, làm loãng tín hiệu. Chỉ token trả lời mới là thứ ta muốn mô hình học cách sinh.
✗ "Chia tử cho tổng số token cả chuỗi."
Mẫu số phải là Σ mặt nạ (số token trả lời), không phải N. Chia sai mẫu → loss bé giả tạo.
✗ "Dùng template model A cho model B cũng được."
Mỗi model một kiểu (ChatML, Llama, Gemma…). Sai mốc/vai → lệch phân phối so với lúc train → trả lời kém, loạn vai.
✗ "Quên ‹start›assistant ở cuối vẫn ổn."
Thiếu mốc mở lượt → mô hình không biết tới lượt mình, dễ im lặng hoặc nối nhầm vai.
Rút ra. Chat template gói tin nhắn bằng token đặc biệt đánh dấu vai/lượt (m tin nhắn → 2m+1 mốc); khi huấn luyện, mặt nạ loss che phần prompt (mặt nạ 0 → gradient 0) nên mô hình chỉ học cách trả lời.
